# Промты для агентов: шаги 5г и 5д (только план, запуск по команде)

> **Статус: ничего не запускать без команды пользователя.** Этот файл — план и
> готовые промты. Агент берёт в работу только тот этап, который назван в команде
> («Запусти 5г.1»). Этапы идут по порядку и по одному PR `dev` → `test`.
> Источники требований: `PLAN.md` (шаги 5г, 5д), `BACKLOG.md`,
> `UI_SKETCHES.md` (v1 — текущая), `UI_SKETCHES_V2.md` (предложение, **не
> утверждено**, пока пользователь не скажет).

## Скилы

| Скил | Когда | Зачем |
|---|---|---|
| `reminder-bot-project` | **Всегда, первым действием** | Окружение (Mac/Pi), `$PY`, временные папки, git-процесс, UI-принципы, инварианты предметной области, тесты |
| `agent-customization` | Только если этап меняет сам скил или файлы инструкций | Правки `SKILL.md` (единственный источник: `.github/skills/`) |

Других скилов этим этапам не нужно. Скил — единый файл `.github/skills/reminder-bot-project/SKILL.md`
(`.claude/skills` и `.agents/skills` — симлинки на него), править только его.

## Решения, которые нужны от пользователя до запуска

- **D1 (5г.2).** Вариант **A (рекомендуется)**: только перенос экрана — у
  `group_reminders` колонка `task` уже есть (миграция в `service_registry.py`,
  `list_group_reminders`); напоминания с `task IS NULL` показываются как
  «Всё служение». Вариант B: менять модель данных — не требуется по тексту PLAN.
- **D2 (5д.1).** Утверждён ли `UI_SKETCHES_V2.md`? Если нет — путь в заголовках
  делается на текущей структуре меню v1.
- **D3 (5д.3).** Где показывать короткое имя: только в сообщениях участникам
  (чат служения, напоминания, график) или и в админских экранах? Рекомендация:
  в сообщениях участникам и в графике; в админских экранах и карточке — полное имя.

Если решения нет, агент **останавливается и спрашивает** (инструмент вопроса), а не выбирает сам.

## Общий промт-обёртка (подставляется в каждый этап)

```
Роль: разработчик reminder_bot. Этап: <ID и название из списка ниже>.

0. Первым действием вызови скил reminder-bot-project и следуй ему (окружение
   определи через `uname -s`; $PY, TMPDIR и временные папки — из его таблицы;
   общий venv не пересоздавай).
1. `git fetch`, `git status -sb`. Работай только в ветке dev; если dev отстаёт
   от origin/dev — `git merge origin/dev` до правок. Чужие изменения не трогай.
2. Прочитай разделы PLAN.md (шаги 5г/5д), блок этапа ниже и перечисленные
   функции в коде. Номера строк в промте ориентировочные — ищи по имени.
3. Если для этапа есть нерешённое решение (D1–D3) — остановись и спроси.
4. Сделай минимальные правки этапа. Не меняй форматы callback_data
   (≤ 64 байт UTF-8), права доступа, подтверждения и идемпотентность доставки.
   Новые экраны — по UI-принципам скила; у каждого экрана «⬅️ К …».
5. Тесты: обнови затронутые и добавь новые (успех + граничные случаи).
   Сначала целевые модули, затем `discover -s tests -q` в фоне с логом,
   `compileall -q bot tests`, `git diff --check`.
6. Документы в том же изменении: UI_SKETCHES.md, docs/ADMIN_GUIDE.md,
   docs/VOLUNTEER_GUIDE.md (если видно участникам), статус этапа в PLAN.md и
   EXECUTION_PLAN.md. Если этап меняет правила для агентов — SKILL.md.
7. Перед коммитом: просмотр диффа отдельной моделью (только ошибки
   корректности, с file:line и сценарием отказа); проверь находки по коду,
   исправь реальные, коротко доложи.
8. СТОП. Покажи итог: что изменено, тесты, находки ревью. Коммит, пуш и PR
   dev → test — только по команде пользователя. После PR: комментарий
   `/review` и ожидание greptile (`greptile_watch.sh`) до «5/5» без новых
   замечаний; после слияния — чек-лист кнопок для проверки в тестовом боте.
Нельзя: отправлять сообщения в Telegram, трогать боевые окружения и токены,
печатать токены и данные участников, начинать следующий этап.
```

## Этап 5г.1 — список напоминаний текстом (требование 6)

**Цель.** Вместо технического «0 дн. · 18:00 · по умолчанию» — компактная строка:
`[день недели] [время] [✅/⏸] [начало первой строки текста]`; примеры дней:
«вс», «ср −1 → вт». Под списком кнопки «1», «2», … открывают напоминание.

**Где в коде (искать по имени).**
`show_notification_settings_menu` (в `bot/handlers.py`, строка списка собирается
из `registry.list_group_reminders`; сейчас метка `f"{reminder_days} дн. · …"`),
карточка напоминания (`group_reminder:open:…`), `reminder_period_status`,
расчёт дат — общий хелпер `next_reminder_occurrence`/`reminder_occurrence` в
`bot/scheduler.py` (не дублировать арифметику дат).

**Требования.**
- День недели считается от дня события (воскресенье) минус `reminder_days`;
  `reminder_days = 0` — «вс».
- Текст — первая строка тела; если `body IS NULL` — «по умолчанию» / «свой
  шаблон служения» (как сейчас различается).
- Статусы периода (`pending`/`ended`) сохранить (⏳/⏸).
- Нумерованные кнопки: `callback_data` прежний `group_reminder:open:{service}:{session}:{id}`;
  не класть текст в callback. Для ≥ 8 напоминаний — существующая пагинация
  (`bot/ui.py`: `layout_buttons`, страницы), навигация отдельным нижним рядом.
- Эмодзи в метках — в списке известных иконок `_send_dialog`.

**Тесты.** `tests/test_handlers.py` (секция групповых напоминаний, ~`916–1083`,
`1116+`), `tests/test_reminder_period.py`, `tests/test_scheduler.py` (хелпер
дня недели), `tests/test_ui.py` (раскладка кнопок). Добавить: день `0`, день
`≥ 1` (переход через неделю), выключенное, период закончился, длинный текст
(обрезка «…»), 10+ напоминаний.

**Документы.** UI_SKETCHES.md (экран «Напоминания и шаблоны»), ADMIN_GUIDE.md.

**Готово, когда:** список читается без слов «дн.», кнопки открывают нужное
напоминание, тесты зелёные.

## Этап 5г.2 — напоминания внутри «Задач» (требование 7, решение D1 = A)

**Цель.** Раздел «⏰ Напоминания и шаблоны» переезжает в «Задачи служения»:
напоминания привязаны к задачам; без задачи — пункт «Всё служение».

**Где в коде.** `settings_keyboard` (кнопка «⏰ Напоминания и шаблоны» →
`service:edit_notify`), `service:service_notify`, обработчик `svc_tasks:*`
(экран задач), `group_reminder:*`, `list_group_reminders` / поле `task`
(`service_registry.py`), `/service_notify` (команда должна работать как раньше).

**Требования.**
- Из карточки/меню убрать отдельную кнопку; вход — из экрана задач
  (`svc_tasks:*`). `/service_notify` и старые callback-ы
  `service:edit_notify:*` / `service:service_notify:*` продолжают работать
  (старые сообщения с кнопками не должны ломаться).
- На экране задач: список задач, у каждой число напоминаний; «Всё служение»
  (`task IS NULL`) и шаблоны (по умолчанию, «📋 Отчёт админам») — рядом.
- Права, сессии (`pending_inputs`, `session_id`), «✅ Завершить и сохранить»
  и `notify_cancel` — без изменений по смыслу.
- Не менять модель данных и расписание отправки.

**Тесты.** `tests/test_handlers.py` (вход в раздел, `/service_notify`,
устаревшая кнопка), `tests/test_admin_report.py` (`433, 469`),
`tests/test_reminder_period.py`, `tests/test_navigation.py` (кнопка «⬅️ К …»).

**Документы.** UI_SKETCHES.md (карточка, задачи, напоминания), ADMIN_GUIDE.md.

**Готово, когда:** все прежние действия с напоминаниями доступны из «Задач»,
старые callback-ы не падают, права не ослаблены.

## Этап 5г.3 — «Закрыть настройку» сразу на первый экран (требование 8)

**Цель.** После «✖️ Закрыть настройку» пользователь сразу видит первый экран
служения, без промежуточного «Настройка закрыта…» с двумя кнопками.

**Где в коде.** `on_notification_setting_cancel` (`notify_cancel:`; сейчас
отправляет «Настройка закрыта…» + `service_result_keyboard`), аналоги у других
сессий настройки (поиск по `"Закрыть настройку"`), `bot/navigation.py`
(`_CLOSE_TEXTS`, `back_callback`, `on_nav_button`).

**Требования.**
- Сохранить проверки устаревшей сессии (`session_id`, шаг, чат).
- Корневой экран — карточка служения (определи по `service:service_settings`);
  краткое «изменения сохранены/не сохранены» — тостом (`_answer_callback`,
  ≤ 200 символов) или строкой в начале экрана.
- Не ломать «↩️ Отмена»/«🏠 В начало»: проверить `back_callback` и `nav_state`.

**Тесты.** `tests/test_handlers.py` (около `916+`: сейчас фиксирует
промежуточный экран), `tests/test_navigation.py` (`56–67`). Добавить: устаревшая
сессия, закрытие после изменения, закрытие без изменений.

**Документы.** UI_SKETCHES.md, ADMIN_GUIDE.md.

## Этап 5д.1 — «График» → «Обзор» и путь в заголовках (требования 14, 15; решение D2)

**Цель.** (14) в «📅 График» кнопка «График» → «Обзор». (15) заголовок экрана
служения — путь: `ЗВУК › 📅 График › Обзор`, последний пункт — название нажатой кнопки.

**Где в коде.** `settings_keyboard` (кнопка «📅 График», `rdy:open:{service}`),
экраны `rdy:*` (`show_readiness` и родственные), `service_label`,
`bot/navigation.py` (`_BACK_PREFIXES`: «⬅️ К », «↩️ К », «⬅️ Назад»).

**Требования.**
- Один хелпер `screen_title(service, *path)` — не собирать пути вручную на
  каждом экране; названия берутся из подписей кнопок без служебных эмодзи-дублей.
- Только видимый текст: `callback_data` не менять (лимит 64 байта).
- Подписи кнопок «⬅️ К …» не менять — иначе сломается распознавание
  «назад» в `navigation.py`; если меняешь — обнови `_BACK_PREFIXES` и тесты.
- Вносить поэтапно: сначала разделы «График» и «Задачи», остальные — по списку
  в промте пользователя; длинные пути укорачивать «…» (лимит текста Telegram
  считать через `visible_units()`).

**Тесты.** `tests/test_handlers.py` (навигация по графику),
`tests/test_replacement.py` (`629–782`), `tests/test_schedule_plan.py`
(`1455`, `1685`, `1721`), `tests/test_navigation.py`, `tests/test_ui.py`.

**Документы.** UI_SKETCHES.md (все затронутые экраны), ADMIN_GUIDE.md.

## Этап 5д.2 — настройки: ссылки и «Отключить служение» (требования 12, 13)

**Цель.** (12) в «⚙️ Настройки» — название подключённого чата и имена админов
ссылкой на профиль (`tg://user?id=` или `@username`). (13) «⛔ Отключить
служение» — на первом экране «⚙️ Настройки», только суперадмину.

**Где в коде.** `settings_text` и `group_chat_title` (текст настроек),
`service_setup_keyboard` («⚙️ Настройки»), `service_chat_keyboard` (сейчас там
«🔴 Отключить служение», callback `service:service_chat_disable:{service}`),
обработчик отключения (около `set_service_enabled`), `registry.list_service_admins`,
`bot/ui.py`: `user_link()`, `code()`.

**Требования.**
- Ссылки — только через маркеры `user_link()` (HTML руками не собирать);
  у админа без username — ссылка по ID, имя берётся из того, что бот знает.
- Не показывать Telegram ID в тексте экрана.
- Кнопка «Отключить служение» видна только `registry.is_super_admin`; обработчик
  **повторно** проверяет права; перенос с экрана чата — старый callback
  продолжает работать (или даёт понятный ответ), подтверждение действия сохранить.
- Отключённое служение: напоминания/опросы не уходят (как сейчас).

**Тесты.** `tests/test_handlers.py` (права суперадмина/админа служения,
устаревший callback, отображение ссылок), `tests/test_ui.py` (маркеры),
`tests/test_service_registry.py`.

**Документы.** UI_SKETCHES.md, ADMIN_GUIDE.md.

## Этап 5д.3 — короткое имя ответственного (требование 11; решение D3)

**Цель.** У ответственного — поле «Короткое имя для графика и напоминаний»
(«Василий», «В. П.»). Заполнено — подставляется в сообщения участникам; полное
имя остаётся в карточке и для чтения Excel; пусто — как сейчас.

**Где в коде.** Карточка человека (`show_member_card`, `mbr:*`), таблица
`service_members` (+ миграция: новая колонка, безопасная повторно, с дефолтом),
рендер имён: `bot/presentation.py` (`person_label`, `format_task_responsibles`,
`personal_schedule_lines`), `bot/schedule_plan.py` (текст и публикация графика),
`bot/readiness.py` (вступление, прогресс), `bot/admin_report.py`.

**Требования.**
- Короткое имя — **только слой отображения**. Сопоставление «(задача, имя)» с
  Excel, привязки, замены и ключи планировщика остаются по полному имени;
  не добавлять сопоставления только по имени.
- Однофамильцы/одинаковые короткие имена: показывать различимо (как в
  `own_days_note`) или предупреждать при вводе.
- Ввод: пример формата и кнопка очистки; лимит длины; без `\x00` и разметки.
- Миграция: `ALTER TABLE … ADD COLUMN`, безопасно при повторе; если пересоздаёшь
  таблицу — `BEGIN IMMEDIATE;`; снимок бэкапа охватывает новую колонку.

**Тесты.** `tests/test_handlers.py` (`7377–7646`: карточка), `tests/test_presentation.py`,
`tests/test_schedule_plan.py`, `tests/test_admin_report.py`, `tests/test_readiness.py`,
`tests/test_service_registry.py` (миграция), `tests/test_backup.py` при изменении схемы.

**Документы.** UI_SKETCHES.md, ADMIN_GUIDE.md, VOLUNTEER_GUIDE.md.

## Порядок и риски

1. 5г.1 → 5г.2 (общий рендер списка); 5г.3 независим.
2. 5д.1 меняет подписи на многих экранах — после 5г, чтобы не переделывать.
3. 5д.2 независим; 5д.3 последним (затрагивает рендер всех сообщений).
4. Общий риск — `bot/navigation.py`: подписи кнопок «⬅️ К …»/«✖️ Закрыть настройку»
   определяют «назад»; любое переименование требует тестов `test_navigation.py`.
5. Тесты `tests/test_handlers.py` часто проверяют тексты кнопок — искать по
   подстроке старой подписи перед правкой.
