# reminder_bot

Telegram-бот напоминаний по расписанию для Raspberry Pi.

## Установка

```bash
cd /home/pi/app/reminder_bot/prod      # или .../test
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp reminder_bot_credentials.env.example reminder_bot_credentials.env
# ... заполнить BOT_TOKEN, ADMIN_TG_ID, GROUP_CHAT_ID, YANDEX_PUBLIC_URL
```

Управление
./reminder_bot_manage.sh start
./reminder_bot_manage.sh status
./reminder_bot_manage.sh logs
./reminder_bot_manage.sh debug-logs
./reminder_bot_manage.sh logs --follow
./reminder_bot_manage.sh backup
./reminder_bot_manage.sh stop

Команды `logs` и `debug-logs` по умолчанию выводят последние строки и завершаются. Для непрерывного слежения укажите `--follow`.

## Сценарии взаимодействия пользователя с ботом

Сценарии, в которых участвует пользователь, реализованы в Telegram-обработчиках и обычно запускаются в личном чате с ботом. В отличие от регулярной рассылки по расписанию, администрирование сервисов и настроек выполняется вручную через команды, не требующие запуска бота напрямую.

### Базовый рабочий сценарий

1. Администратор запускает бота в личном чате командой `/start`.
2. Для просмотра доступных сервисов и прав используется `/services`.
3. Команда `/service_settings` показывает кнопки доступных служений; выберите
   нужное, чтобы посмотреть его настройки.
4. Команда `/service_chat` позволяет выбрать служение и задать или отключить
   его групповой чат.
5. Команда `/service_sync` перечитывает задачи и ответственных из Excel-графика
   выбранного служения и показывает, кому ещё нужно сопоставить Telegram.
6. Команда `/service_contact` позволяет выбирать задачу и ответственного из
   графика и сопоставлять их с пользователем кнопкой Telegram или ручным
   вводом ID и username.
7. Команда `/service_notify` открывает меню выборочного изменения параметров
   напоминаний. Перед вводом шаблона показываются сохранённый текст и пример
   для предстоящего воскресенья с текущими назначениями и привязками.
   Неизменённые значения сохраняются; настройку можно сохранить или отменить.
8. `/test_notify` предлагает выбрать служение и вид проверки: отправить
   помеченное тестовое сообщение в его группу либо получить в личном чате
   предпросмотр группового и персональных текстов именно выбранного служения.
   Участникам персональные сообщения не отправляются.
9. Любой пошаговый сценарий можно прервать командой `/cancel`.

### Команды и их назначение

```text
/start
/services
/service_settings
/service_admin_add
/service_admin_remove
/service_chat
/service_contact
/service_sync
/service_notify
/test_notify
/cancel
```

- `/services` — список доступных служений; супер-администратор видит все, администратор видит каждое служение, на которое назначен.
- `/service_settings` — кнопками выбрать служение и показать его текущий чат, шаблоны и параметры напоминаний.
- `/service_admin_add` — выбрать служение кнопкой, затем выбрать пользователя Telegram или ввести его ID и необязательный username; подтвердить назначение. ID позволяет добавить самого себя.
- `/service_admin_remove` — выбрать служение кнопкой и указать Telegram ID удаляемого администратора.
- `/service_chat` — выбрать служение кнопкой, затем настроить групповой чат или отключить служение.
- `/service_contact` — выбрать служение, задачу и имя ответственного из актуального расписания; затем выбрать пользователя кнопкой или ввести ID и необязательный username. После подтверждения или отмены список связей задачи открывается снова, чтобы можно было назначить или заменить другую связь. Кнопка «Возврат к задачам» возвращает к выбору задачи, а «Возврат к выбору служения» — к списку служений.
- `/service_sync` — только для супер-администратора: перечитать месячный график выбранного служения и показать задачи, ответственных и текущие привязки, чтобы найти новые или изменившиеся назначения.
- `/service_notify` — выбрать служение и настройки для изменения: дни, время, групповой текст или личный шаблон задачи. При выборе шаблона показываются текущий текст и пример на предстоящее воскресенье. После изменения можно вернуться к меню, завершить и сохранить либо отменить.
- `/test_notify` — выбрать служение и режим: проверить отправку помеченного тестового сообщения в настроенную группу или отправить главному администратору предпросмотр текстов выбранного служения. Участникам тестовые личные сообщения не отправляются.
- `/cancel` — прервать текущий пошаговый диалог и вернуться к обычному режиму.

Служение для административных команд выбирается кнопкой из списка; вводить
технический идентификатор не требуется. Супер-администратор видит в `/services`
Telegram ID и сохранённые username администраторов. У служения может быть
несколько администраторов, и один пользователь может администрировать несколько
служений. Для удаления администратора нужен его Telegram ID.

#### Пример: настроить службу «Звук»

Все команды ниже выполняются супер-администратором в личном чате с ботом.

1. Отправьте `/services`, чтобы проверить доступные служения.
2. Отправьте `/service_chat`, выберите «Звук» и нажмите кнопку выбора группового чата,
   выберите группу, в которой бот уже состоит. Бот сохранит чат и включит
   службу в реестре.
3. Отправьте `/service_admin_add`, выберите «Звук», затем выберите пользователя
   кнопкой Telegram либо введите `123456789 @username` (username необязателен).
   Супер-администратор может ввести собственный ID, чтобы назначить себя.
   Проверьте сведения и подтвердите назначение.
4. Отправьте `/service_sync` и выберите «Звук». Бот перечитает график,
   покажет задачи и ответственных из Excel вместе с имеющимися Telegram-привязками.
   Для нового или изменившегося ответственного выберите задачу и имя, затем
   сопоставьте его с пользователем Telegram кнопкой или вводом ID и
   необязательного username и подтвердите выбор.
5. `/service_contact` запускает ту же привязку вручную: выберите «Звук»,
   задачу и имя ответственного из текущего Excel-графика. Нажмите кнопку
   выбора пользователя Telegram либо отправьте ID и необязательный username,
   затем подтвердите привязку. Вручную вписать произвольную задачу или имя
   нельзя. После подтверждения или отмены список связей задачи появится снова:
   можно изменить следующую запись, перейти к другой задаче или завершить.
6. Отправьте `/service_notify`, выберите «Звук» и нажмите кнопку только у тех
   параметров, которые хотите изменить. При редактировании группового или
   личного шаблона сначала показываются ранее сохранённый текст и пример
   сообщения на предстоящее воскресенье с актуальными назначениями и
   пользовательскими привязками. При редактировании личного шаблона задача
   выбирается из расписания. После каждого изменения бот возвращает в
   меню; нажмите «Завершить и сохранить» для сохранения всех изменений или
   «Отмена», чтобы отказаться от них. `/cancel` прерывает незавершённый ввод.
7. Отправьте `/service_settings` и выберите «Звук», чтобы проверить сохранённые
   настройки.
8. Отправьте `/test_notify`, выберите «Звук», затем один из вариантов:
   «Проверить отправку в групповой чат» отправит только помеченное тестовое
   сообщение в его группу; «Показать тексты админу» пришлёт предпросмотр
   группового текста и персональных шаблонов только главному администратору.

Команды настройки
чата, администратора и ответственных доступны супер-администратору; изменение
уведомлений доступно супер-администратору и администратору этой службы.
Удаление администратора выполняется через `/service_admin_remove`: сначала
выберите служение кнопкой, затем укажите Telegram ID из списка.

**Важно о текущем объёме функционала:** для «Звука» и остальных служб, кроме
«Собрания», команды сохраняют конфигурацию, но их расписание и настройки пока
не подключены к плановой отправке. В режиме предпросмотра `/test_notify`
показывает данные выбранного служения и не отправляет участникам сообщения.

### Сценарий для админа сервиса

Администратор сервиса:

1. Использует `/services` и получает только свой сервис.
2. Вызывает `/service_settings` и выбирает своё служение, чтобы посмотреть настройки.
3. Использует `/service_notify`, выбирает службу и выборочно редактирует её параметры, если у него есть доступ.
4. Не может менять настройки других сервисов и не видит список администраторов других команд.

### Операционный чеклист для администратора

Ниже — короткая пошаговая последовательность, которую обычно используют при первой настройке сервиса и при регулярной поддержке.

#### 1. Подготовка доступа

- В личном чате с ботом вызовите `/start`.
- Убедитесь, что вы зарегистрированы в списке супер-администраторов или администраторов конкретного сервиса.
- Проверьте доступные команды через `/services`.

#### 2. Назначение группового чата

- Выполните `/service_chat` и выберите служение кнопкой.
- Нажмите кнопку выбора чата и выберите группу, в которой бот уже состоит.
- Бот сохранит чат и включит службу. Проверьте результат через `/services`.

#### 3. Назначение администраторов

- Выполните `/service_admin_add` и выберите служение кнопкой.
- Выберите пользователя кнопкой Telegram.
- Подтвердите назначение.
- При необходимости удалите лишнего администратора через `/service_admin_remove`, выбрав служение и введя Telegram ID.

#### 4. Привязка ответственных лиц

- Выполните `/service_sync` для сверки актуального графика и привязок либо `/service_contact` для перехода к привязке.
- Выберите задачу, а затем имя ответственного из текущего Excel-расписания.
- Нажмите кнопку выбора пользователя Telegram, выберите аккаунт и проверьте имя и ID.
- Подтвердите привязку.
- Проверьте, что связанный Telegram ID соответствует человеку, а username при необходимости корректный.

#### 5. Настройка напоминаний

- Выполните `/service_notify`, выберите службу и параметр для редактирования.
- После каждого ввода вернитесь в меню; сохраните кнопкой «Завершить и сохранить» либо отбросьте изменения кнопкой «Отмена».
- Для индивидуального текста выберите задачу из списка; можно использовать `{name}` и `{sunday_date}`.

#### 6. Проверка перед запуском

- Выполните `/test_notify`.
- Выберите служение и нужную проверку: отправку теста в его групповой чат
  либо предпросмотр текстов, который будет отправлен только главному
  администратору.
- Личные сообщения участникам не отправляются.
- Для выбранной службы предпросмотр учитывает её расписание, контакты и шаблоны.

#### 7. Ежедневная поддержка

- После обновления графика запускайте `/service_sync` и выбирайте нужное служение; сопоставьте новые имена ответственным пользователям Telegram.
- При смене чат-группы повторите `/service_chat`.
- Если нужно исправить тексты уведомлений — используйте `/service_notify`.
- Для новых сервисов или ролей сначала обновляйте Excel-расписание, затем проверяйте привязки и шаблоны.
- Помните, что пока только «Собрание» связано с действующей плановой рассылкой;
  остальные службы хранят настройки, но не рассылают уведомления по расписанию.

Аргументы CLI бота
Бот запускается только через manage.sh и всегда принимает:

--shm-dir — директория ОЗУ (/dev/shm/reminder_bot/{test|prod})

--log-dir — директория логов (по умолчанию = --shm-dir)

При запуске через `manage.sh` директорию логов можно переопределить переменной `LOG_DIR`, не меняя `SHM_DIR`, например: `LOG_DIR=/var/log/reminder_bot ./manage.sh start`.

Каталоги `--shm-dir` и `--log-dir` должны принадлежать пользователю бота, не содержать символических ссылок в компонентах пути и быть недоступны группе и другим пользователям. `manage.sh` настраивает каталоги с правами `700`; приложение атомарно создает и при штатной остановке удаляет PID-файл с правами `600`. `manage.sh` ожидает его появления и сверяет PID и время старта с запущенным процессом; при старте он может удалить только устаревший PID-файл.

Файлы логов и бэкапы создаются с правами `600`; каталог бэкапов `logs_backup` настраивается с правами `700`. Debug-лог содержит найденные для рассылки имя, Telegram username, Telegram ID и подготовленные тексты сообщений; не публикуйте этот файл.

## Процесс разработки и развертывания

1. Разработка ведётся в ветке `dev` и локальной папке `src`.
2. При PR `dev -> test` сначала выполняются unit-тесты. Если они успешны,
   workflow копирует commit из `dev` в `/mnt/external_data/reminder_bot/test`
   и запускает тестовый экземпляр бота. Он остаётся запущенным для ручной
   проверки; данные и логи тестового экземпляра находятся в
   `/dev/shm/reminder_bot/test`.
3. Если при проверке найдены ошибки, исправления коммитятся в `dev`.
   Обновлённый PR повторно запускает тесты и обновляет тестовую копию.
4. После ручной проверки и review PR `dev -> main` проходит unit-тесты, но не
   меняет production. После merge в `main` workflow синхронизирует проект в
   `/home/pi/app/reminder_bot/prod` и запускает отдельный production-экземпляр
   с данными и логами в `/dev/shm/reminder_bot/prod`.

Подробная спецификация процесса находится в разделе 7 файла
[zt.txt](./zt.txt). Workflow не выгружает runtime-логи с персональными данными
в GitHub artifacts.

Если по части ролей не хватает назначения или Telegram ID, бот уведомляет администратора, но всё равно отправляет сообщение в группу и личные сообщения участникам, чьи данные сопоставлены. Известный username показывается в группе даже без Telegram ID; для отсутствующей отметки используется текст «не найден». Успешные отправки сохраняются отдельно: при следующем запуске повторяются только неудавшиеся сообщения, а исправление неполного расписания обновляет групповое сообщение и добавляет доступные личные уведомления.

В тестовой и рабочей папках используется отдельное окружение `venv/`; зависимости одного окружения не обновляют другое.

Каталог служений и чтение много-служебной книги
В `bot/services.py` зарегистрированы восемь служений: «Собрание»,
«Звук», «Спевка», «Слайды», «Трансляция», «Орг. порядка», «Кухня» и «Кофе».
`parse_service_events()` в `bot/excel_parser.py` читает даты и назначенных
ответственных из их горизонтальных блоков на месячном листе. Этот парсерный
этап не меняет действующую рассылку: в планировщике пока используется прежняя
логика «Собрания». Персональные Telegram ID для новых служений будут связываться
с назначенными именами отдельно, согласно принятому решению об управлении
контактами супер-администратором.

Управление служениями в Telegram
Команды управления доступны только в личном чате с ботом. Супер-администратор
определяется записью в реестре; администратор служения может просматривать и
изменять настройки уведомлений только назначенной ему службы.
Названия служб в сообщениях выводятся по-русски заглавными буквами. Если
запустить команду без параметров, бот предложит выбрать служение кнопкой, затем
проведёт по шагам. Вводить технический ID служения не требуется. Список команд
Telegram содержит краткие описания; `/cancel` отменяет текущий диалог.

```text
/services
/service_settings
/service_admin_add
/service_admin_remove
/service_chat
/service_contact
/service_sync
/service_notify
/test_notify
/cancel
```

`/services` показывает полный список супер-администратору и все назначенные
этому пользователю служения администратору; между описаниями служений есть пустая
строка. Супер-администратор видит Telegram ID и сохранённые username
администраторов. Для одной службы разрешено несколько администраторов, а один
пользователь может быть администратором нескольких служб. Команды назначения
администраторов, настройки чата и привязки ответственных доступны только
супер-администратору. Команда
`/service_admin_remove` после выбора служения попросит Telegram ID удаляемого
администратора. При добавлении администратора и привязке ответственного бот
предлагает выбрать пользователя средствами Telegram либо ввести его ID и
необязательный username в одном сообщении (например, `123456789 @username`).
Это позволяет супер-администратору назначить самого себя. Назначение
подтверждается отдельной кнопкой. Чтобы настроить чат, выберите группу, в которой бот уже состоит.
Чтобы отключить служение, выберите соответствующее действие кнопкой; ID чата
при этом сохраняется. Только супер-администратор может запустить `/service_sync`: команда перечитывает
месячный график выбранного служения и показывает задачи, ответственных и актуальные привязки. Выберите ответственное
имя, если ему нужно назначить или изменить Telegram-пользователя. После
подтверждения или отмены бот повторно показывает связи выбранной задачи и
кнопки для изменения следующего ответственного, возврата к задачам или
завершения. Задачу и имя произвольно вводить нельзя.
`/test_notify` сначала предлагает выбрать служение, затем действие: проверить
доставку помеченного тестового сообщения в настроенную группу или отправить
главному администратору предпросмотр настроенных текстов и назначений выбранной
службы. Предпросмотр не отправляется участникам.
Для «Собрания» переключатель немедленно влияет на старую плановую рассылку:
при `off` уведомления не отправляются. Выбранные через команду ID чата и статус
сохраняются при перезапуске и не перезаписываются значениями credentials.
Команда `/service_contact` позволяет вручную перейти к задаче и имени из
расписания для привязки пользователя кнопкой Telegram либо по введённому ID и
необязательному username; вручную добавить задачу или имя нельзя.
`/service_notify` открывает меню редактирования дней, времени, текста группы и
личных шаблонов. Изменяйте только нужные параметры: остальные значения
сохраняются. На шагах ввода доступны действия «Завершить и сохранить» и
«Отмена»; длинные списки задач разбиваются на страницы. Для группового текста
доступны `{service_name}`, `{sunday_date}`, `{task_assignments}`; в личных
шаблонах — `{name}`, `{task}`, `{service_name}`, `{sunday_date}`,
`{telegram_id}`, `{username}`. Настройки сохраняются в реестре;
перед вводом нового текста бот показывает сохранённый шаблон и пример его
рендеринга на предстоящее воскресенье для актуальных назначений и привязок.
подключение новых служб к фактическому планированию и рассылке будет отдельным
этапом, поэтому эта команда пока не меняет действующую рассылку «Собрания».

Постоянная конфигурация служений
При запуске бот инициализирует SQLite-реестр служений, администраторов
(Telegram ID и username), групповых чатов, привязок ответственных и аудита
изменений.
По умолчанию база создаётся в `.runtime/reminder_bot.sqlite3` с закрытыми
правами доступа; для другого пути задайте `REMINDER_BOT_DB_PATH` в credentials
или окружении процесса. Относительный путь считается от корня проекта.
Текущий `ADMIN_TG_ID` становится первым
супер-администратором только при создании пустого реестра. «Собрание»
инициализируется включённым с существующим `GROUP_CHAT_ID`; остальные служения
пока выключены и не получают групповой ID автоматически. Подключение новых
рассылок будет добавлено отдельным этапом.

### Проверка целостности SQLite

База данных хранится в SQLite и должна проходить встроенную проверку на
целостность перед использованием в продакшене. Проверку можно выполнить
напрямую из командной строки:

```bash
python - <<'PY'
import sqlite3
from pathlib import Path
path = Path('.runtime/reminder_bot.sqlite3')
if not path.exists():
    raise SystemExit('SQLite-файл не найден: ' + str(path))
with sqlite3.connect(path) as conn:
    result = conn.execute('PRAGMA integrity_check;').fetchone()
    print(result[0] if result else 'unknown')
PY
```

Ожидаемый результат: `ok`.
Если база повреждена, SQLite вернёт иной результат или выбросит ошибку;
в этом случае требуется восстановление из бэкапа или пересоздание реестра
с повторной настройкой служений.

Проверка Excel без рассылки
Для отладки скачивания и парсинга используйте отдельную команду, которая не запускает бота и не отправляет сообщения:

```bash
/home/pi/.venv/bin/python -m bot.debug_schedule
/home/pi/.venv/bin/python -m bot.debug_schedule --date 2026-10-11
```

Файл и debug-лог сохраняются вместе и не удаляются автоматически в
`/dev/shm/reminder_bot/debug/` (права каталога `700`, файлов `600`).
Путь к скачанному файлу печатается в выводе команды.
Можно указать другой приватный каталог через `--output-dir`; каталог должен
принадлежать текущему пользователю и быть недоступен группе и другим.
Удаляйте сохраненные файлы вручную после отладки.

Проверка доставки Telegram без ожидания расписания
Администратор может отправить боту команду `/test_notify` в личном чате.
После выбора служения можно отдельно проверить отправку помеченного сообщения
в его настроенную группу или показать главному администратору предпросмотр.
Предпросмотр строится для выбранного служения по актуальному графику на
ближайшее воскресенье, сохранённым привязкам и шаблонам. При предпросмотре
сообщение в группу не отправляется; ни один из режимов не отправляет личные
сообщения участникам и не меняет состояние плановой рассылки.
Вызов из группового чата или пользователем, не являющимся администратором,
игнорируется без ответа.

Проектный skill для повторного использования этого workflow находится в

Структура
reminder_bot.py — точка входа

bot/cli.py — argparse

bot/debug_schedule.py — безопасная отладочная проверка xlsx без рассылки

bot/config.py — загрузка креденшелов/шаблонов/расписания

bot/logger.py — interaction + debug логгеры

bot/state.py — кэш текущей недели

bot/yandex_disk.py — скачивание xlsx с retry 3×5 мин

bot/excel_parser.py — парсинг месячных листов расписания и «Списки»
Парсер пересчитывает фактические размеры листов, если в xlsx ошибочно указан диапазон A1, и нормализует известный некорректный стиль границ только в памяти, не меняя исходный файл.

bot/scheduler.py — APScheduler

bot/notifier.py — веерная рассылка с rate limit 0.05 c

bot/handlers.py — callback «Принял, буду»
Регистрация обработчиков выполняется через `register(dispatcher, context)`, чтобы роутер обязательно подключался к диспетчеру.

bot/app.py — сборка, сигналы, PID-файл
